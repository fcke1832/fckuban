Branch: `update_libs`

run the test suite and record the result. **Application code and tests were not

## 6. Problems found outside the test suite (probes, not in `tests.py`)

I rendered every registered admin add page and every admin changelist with a
logged-in superuser, and ran the migration/diagnostic commands. Two pages 500:

### 6.1. News admin add/change page — HTTP 500

```
TypeError: AdminImageWidget.render() got an unexpected keyword argument 'renderer'
```

- Where: `news/admin.py:13` — `def render(self, name, value, attrs=None):`
- Why: since Django 2.1 `BoundField.as_widget()` always passes `renderer=...`;
  the override does not accept it. Confirmed by BUGS.md item 7.
- Impact: you cannot add or edit a news item in the admin at all.

### 6.2. Tournament admin add/change page — HTTP 500

```
TemplateSyntaxError: 'admin_static' is not a registered tag library.
```

- Where: `tournaments/templates/admin/tournaments_change_form.html:2` —
  `{% load static admin_static %}`.
- Why: `admin_static` was removed in Django 3.0 (`static` is the replacement).
- Impact: you cannot add or edit a tournament (the "Пересчитать таблицу"
  button page is gone).
- This issue is **not** listed in BUGS.md; it is new for this upgrade.

### 6.3. BUG-014 is now a hard 500 on the main page

Probe: create a published `News` without an image, request `/`:

```
main page, news without image -> ValueError: falsey file_ argument in get_thumbnail()
```

On Django 2.0.7 the exception inside `{% include %}` was silently swallowed
(the news block just disappeared — exactly as BUGS.md predicted for 2.1+).
Now it propagates → HTTP 500. This is the #1 production blocker of the upgrade.

### 6.4. BUG-023 still blocks real databases

```
uv run python manage.py migrate
# OperationalError: no such column: team_baseteammember.image_hover
```

Same for `uv run pytest` without `--nomigrations` (all 299 tests error at
setup). The suite only runs because `pytest.ini` keeps `--nomigrations`
(temporary workaround documented in BUGS.md / TESTING.md). `manage.py test`
discovers 0 tests (pytest-style tests), so it is not a substitute.

### 6.5. System checks

`manage.py check` → 0 errors, 23 warnings:

- 22 × `models.W042` — auto-created PK, `DEFAULT_AUTO_FIELD` is not set;
- 1 × `fields.W340` — `news.News.hashtags`: `null` has no effect on M2M.

`manage.py makemigrations --check --dry-run` → **No changes detected**, i.e. the
Django/Python upgrade itself does not require a migration.

## 8. Compatibility / instruction conflicts you should know about

1. **Python 3.11 is not supported by Django 3.2.**
   Django docs (3.2 FAQ): *"3.2 — 3.6, 3.7, 3.8, 3.9, 3.10 (added in 3.2.9)"*.
   The pair works here, but any Django bug on 3.11 is "your problem".
   Supported combinations:
   - Python 3.10 + Django 3.2 (fully supported, but 3.2 is EOL);
   - Python 3.11 + Django ≥ 4.1 (supported, closer to the docs' target).
2. **Django 3.2 is EOL** (April 2024) — no security fixes. For a public club
   site this is a real risk.
3. **Conflict with `AGENTS.md` / `BUGS.md` / `TESTING.md`:** they describe the
   target stack as **Django 5.x + Python 3.14+**. Your request in this window is
   Django 3.2 + Python 3.11. I followed your direct request and am reporting the
   contradiction, as `AGENTS.md` asks ("if documentation contradicts the code,
   report it, don't silently pick one").
4. `uv` is now the manager, but `requirements*.txt` (Django 2.0.7) and
   `TESTING.md` (pip, Python 3.6) are stale and can mislead. Left as is.
5. `banner/admin.py:20` `show_banner.allow_tags` is inert since Django 2.1
   (`allow_tags` is ignored). Not used in `list_display`, so no runtime effect,
   but the test `test_show_banner_allow_tags` now pins meaningless behaviour.
